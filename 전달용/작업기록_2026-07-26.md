### ⚠ GROBID on Windows — 소스 패치가 **필수**
공식 릴리스는 얇은 jar 뿐이고 윈도우에서 그냥은 안 돈다. `C:\grobid\grobid` 소스를 3곳 고쳐 빌드했다.
1. `build.gradle` — Mac/Unix 외 플랫폼에서 `throw RuntimeException("Unsupported platform!")` → 윈도우 분기 추가
2. `build.gradle` — `installDist` 에 `duplicatesStrategy = EXCLUDE`
3. `grobid-core/.../DocumentSource.java` — **이게 진짜 블로커**
   - 번들된 윈도우 pdfalto 는 **0.1 버전**(리눅스·맥은 0.5/0.6). kermitt2 는 윈도우 바이너리를 배포하지 않는다.
   - 0.1 은 `<TextBlock>` 없이 `<TextLine>` 을 내보내 파서가 NPE → HTTP 500
   - **`-blocks` 플래그**를 붙여야 블록이 생긴다(테스트 PDF 0개 → 146개)
   - `-noLineNumbers` 거부, 서버모드 `--timeout` 미지원 → 인자 축소 + 스레드 모드
- **JDK 21 필요**(GROBID 0.9.0 이 `JavaLanguageVersion.of(21)` 선언)
- **pdfalto 0.1 은 한글 경로 파일을 못 연다**(Cygwin 빌드). GROBID 서비스는 업로드를
  자기 tmp(ASCII)로 받아 처리하므로 무해하지만, **pdfalto 를 직접 호출하는 코드를 넣으면
  선생님 Dropbox 경로에서 즉시 터진다.**
- **표 검출이 리눅스보다 60% 나쁘다**(같은 134편: TEI 표 231 → 93). 그래서 파일럿 재처리에서
  **옛 TEI(데스크탑 Docker 산출)를 쓰는 쪽을 택했다.**
- 장시간 배치 중 서비스가 죽는다(175편 중 2회). **자동 재기동 필수.**

### ResearchMap 배포 함의
"첫 실행 때 공식 GROBID 다운로드"는 **불가능**하다. 우리가 패치해 빌드한 결과물
(`grobid-service/build/install/grobid-service/lib`, 183 jar, 240MB)을 직접 배포해야 한다.
Apache-2.0 이라 재배포는 가능하나 유지보수 부담이 생긴다.

### 주요 수리 내역

  반환해 "만든 파일을 없다고 판단"하는 사고가 있었다
- `inventory` — 줄바꿈으로 끊긴 DOI 를 후보 생성 + Crossref 존재확인으로 교정
  (`10.1200/jco.18` → `10.1200/jco.18.01223`)

## 8. 태도 규칙 (이번 세션에서 배운 것)

- **규칙 기반 탐지 ≠ 검증.** 미리 생각해 넣은 결함만 잡힌다. 논문을 실제로 읽어야 한다.
- **지표를 낮추는 데 최적화하지 마라.** 미분류 비율을 낮추려다 `Primer`→intro 오분류를
  성과로 착각했다. 틀린 라벨보다 정직한 `other` 가 낫다.
- **서브에이전트 보고를 그대로 믿지 마라.** 구현자가 "주제 가드로 깨끗이 갈렸다(0.00 대 0.41)"
  고 보고한 것이 실측은 0.76~1.00 이었다. 검증자가 잡았다.
- **고쳐서 나빠지는 경로를 경계하라.** recover 의 병합 33건 중 14건이 완결 문장 뒤에 엉뚱한
  조각을 붙였고, 붙고 나면 대문자로 시작해 **탐지기에 다시 안 잡혔다**(결함이 숨는다).
- **수리 전/후를 같은 잣대로 재라.** `verify_all.py` 가 그 역할.
