# ResearchMap 이식 가이드 — 논문 PDF 구조화 추출

작성 2026-07-26 · 대상: ResearchMap 개발자
원본 저장소: https://github.com/jminbae/pdf-extractor (공개)
제품 요구사항은 저장소 루트의 **PRD.md** — 무엇을 왜 만드는지, 무엇이 되면 완성인지.

이 문서 하나로 **PDF Extractor 의 추출 파이프라인을 ResearchMap 안에서 그대로
재현**할 수 있게 쓴다. 코드는 저장소에 있으니 여기서는 **왜 그렇게 되어 있는지**,
**어디서 깨지는지**, **무엇을 건드리면 안 되는지**를 적는다. 그것이 재현에서 실제로
어려운 부분이다.

---

## 0. 무엇을 이식하는가

ResearchMap 은 이미 논문을 읽어들이지만 본문 추출이 부정확·불완전하다. 특히
**표를 표로 못 뽑고, 그림이 없고, 본문 인용과 참고문헌이 이어지지 않는다.**
이 파이프라인이 그 구멍을 메운다.

**두 가지를 함께 옮긴다.**

- **추출** (1~5장) — PDF → 정본 JSON + 그림 PNG
- **화면 표현** (4-B장) — 인용·그림 팝업, 표, 우클릭 복사·저장, 3분할 화면

읽는 경험까지 옮겨야 의미가 있다. 잘 뽑아도 인용을 누를 때 엉뚱한 데로 가면
쓰는 사람에게는 여전히 부정확한 도구다.

입력은 **born-digital 영어 논문 PDF** 한 편, 출력은 **정본 JSON 한 개 + 그림 PNG
여러 장**이다. 검색·색인·화면은 ResearchMap 것을 쓰면 된다 — 이 모듈은 검색 엔진이
아니다.

**실측(2026-07-26, 저장소 203편)**

| 항목 | 값 |
|---|---|
| 추출 경로 | GROBID 194 · PyMuPDF 폴백 8 · PMC XML 1 |
| 품질 점수 평균 | 0.863 |
| 그림 | 384개 중 **331개가 실제 이미지**(86%) |
| 표 | 329개 |
| 참고문헌 | 5,155건 (지면 번호 확정 93%) |

GROBID 를 끄면 이 수치가 무너진다. 폴백은 안전망이지 대안이 아니다
(품질 0.96 → 0.65, 표 286 → 0).

## 1. 한눈에 보기

```
PDF 한 편
  │
  ├─ [0] inventory   PDF 열기·DOI 추출·쪽수·텍스트층 판정·중복 판정
  │                    └ DOI 가 줄바꿈으로 끊기면 후보를 만들어 Crossref 로 확인
  ├─ [b] boundary    합본 지면에서 "이 논문의 구간"을 판정 (레터 여러 편이 한 쪽에)
  │
  ├─ [1] metadata    PubMed·iCite·OpenAlex·Crossref 조회 (파싱하지 않는다)
  │
  ├─ 분기 ┬ PMCID 있음 → [2a] pmc_xml + jats   원문 JATS XML
  │       └ 없음        → [2b] grobid_client   GROBID TEI
  │                        └ 실패 → pdf_fallback (PyMuPDF, 저품질 안전망)
  │
  ├─ [3] schema      두 경로를 **하나의 정본 스키마**로 병합
  │
  ├─ [4.5] textfix   자간 아티팩트·러닝헤더·캡션 누수·섹션 타입 재분류
  ├─ [4.6] recover   GROBID 가 버린 문단 앞부분을 PDF 에서 되살림
  ├─ [4.6] symfont   기호 전용 글꼴 글자 복원 (NOS 별점이 '$' 로 나오던 것)
  ├─ [4.7] captions  그림·표 캡션을 PDF 좌표·글꼴 근거로 확정
  ├─ [4.7] tablefill 표를 PDF 괘선 좌표로 재구성 (PMC 가 표를 이미지로만 준 경우 포함)
  ├─ [4.8] figclip   **그림을 실제 PNG 로 잘라냄**
  ├─ [r]  refmatch   참고문헌: 번호·순서는 지면에서, 내용은 iCite 에서 → 짝짓기
  │
  ├─ [4] qc          품질 점수·게이트
  └─ [a] audit       내용 수준 전수 점검 (선택)
        ↓
  정본 JSON + 그림 PNG
```

진입점은 둘이고 **같은 단계를 탄다**.

- `single.py` — PDF 한 편 (데스크탑 앱이 쓰는 길). **ResearchMap 은 이쪽을 부르면 된다.**
- `run_pilot.py` — 폴더 일괄

> ⚠ 같은 일을 하는 경로가 둘이면 반드시 어긋난다. 실제로 앱 경로에만 `recover`·
> `tablefill` 이 빠져 있어 앱 산출물만 조용히 질이 갈린 적이 있다(표 161개 중
> 49개가 캡션만 남은 빈 표). 단계를 추가하면 **양쪽 다** 넣어야 한다.

## 2. 정본 스키마 (계약)

```
paper_id · source · schema_version · quality_score · source_file · meta
· abstract · abstract_source · body_text · figures · tables · references · qc
```

```
body_text = [{ path[], section_type, paragraphs[
                 { id, text, cited_refs[], cited_keys[], refs_figure[], refs_table[] }
             ]}]
section_type = abstract | intro | methods | results | discussion | back | other
figures    = [{ id, caption, image }]          image = 상대경로 (절대경로 금지)
tables     = [{ id, caption, markdown, pdf_span }]
references = [{ num, doi, pmid, title, authors, journal, year, ... }]
```

이름은 S2ORC 관례를 따랐다(`paper_id`·`body_text`·`abstract`·`figures`·`tables`·
`references`). 다만 **S2ORC 로 내보내지는 않는다** — S2ORC 는 절 계층이 없고
(`section` 문자열 하나), 표 내용이 아예 없으며, 본문에서 인용 마커를 떼어낸다.
셋 다 우리에게 필요하다.

정의는 `src/pubnexus/schema.py`.

## 3. 뒤집지 말 것 (근거 있는 결정들)

각각 실제로 사고가 나서 정해진 것이다.

| 결정 | 이유 |
|---|---|
| **정본은 JSON 하나.** Markdown 은 저장하지 않고 볼 때 렌더 | md 를 저장하면 JSON 수리 후 조용히 낡아 **두 번째(틀린) 정본**이 된다. 렌더는 0.4ms/편 |
| **참고문헌 내용을 PDF 에서 파싱하지 않는다.** iCite(NIH) API 로 조회 | 파싱 참고문헌은 구조적으로 못 믿는다 — DOI 순열 뒤섞임(한 편 125개 중 98개), 이웃 논문 혼입, 자기인용, 펀딩 문구 유입 |
| **번호·순서는 지면, 내용은 iCite → 짝지어 합침** | iCite 순서는 지면 번호가 아니다(실측: 지면 1.Kim 2.Oh 3.Won ↔ iCite Kim·Kramer·자기자신·Won·Oh). 그래야 본문 `[15]` → 목록 15번이 맞는다 |
| **본문 인용은 제자리에 `[15]` 로 남긴다** | 위첨자가 그냥 뽑히면 `효과가 있었다15,16` 이 되어 본문 수치와 구분이 안 된다 |
| **PDF↔정본 짝은 파일 내용(sha1)** | 경로로 맺으면 PDF 를 옮기거나 이름을 바꾸는 순간 추출물을 잃는다 |
| **비영어 논문은 본문을 비우고 서지정보만** | 2단 한글 본문은 읽기 순서가 섞여 `피부의 표 여 있는데` 가 되고 그 문단이 제목 자리까지 올라간다 |
| **틀린 것보다 없는 것이 낫다** | 참고문헌 링크·표 셀 값·잘라낸 그림 전부 이 기준으로 판단했다. 근거가 애매하면 하지 않는다 |
| **GROBID 는 선택이 아니라 필수** | 파일럿 80%가 GROBID 경로 |

## 4. 그림은 어떻게 뽑는가 (`figclip.py`)

**웹에서 받아오지 않는다. 전부 PDF 에서 좌표로 잘라낸다.** PMC 경로로 뽑은 논문도
마찬가지다. 패키지 전체에 그림 이미지를 내려받는 코드는 없다.

그림이 PDF 에 들어 있는 방식은 둘뿐이다.

- **내장 이미지**(임상·현미경 사진) — `page.get_images(full=True)` 로 xref,
  `page.get_image_rects(xref)` 로 지면 좌표를 정확히 얻는다
- **벡터 도형**(forest plot·flow diagram·Kaplan-Meier) — 파일로 박혀 있지 않다.
  `page.get_drawings()` 의 bbox 합집합이 실제로 그려진 범위를 준다

둘을 **같은 조각(piece)** 으로 보고 한 절차에 태운다. 패널 a·b·c 로 나뉘어 있으면
합친 bbox 로 한 장을 만든다.

영역의 기준은 **캡션 좌표**(captions.py 가 글꼴·크기 근거로 확정해 둔다).

1. **세로** — 캡션에서 위로 올라가다 본문 글줄 **블록**이 나오면 멈춘다. 다른 캡션·
   절 제목·러닝헤드·표 영역(`tables[].pdf_span`)도 같은 장벽
2. **가로** — 그 높이에 옆 단 본문이 있으면 그 앞에서 끊고, 없으면 지면 끝까지 연다.
   중간점으로 못박으면 "캡션은 한 단, 그림은 전폭" 조판에서 그림이 반쪽 난다
3. 그 구간 안 조각들의 합집합 bbox 로 좁힌다. **조각이 하나도 없으면 자르지 않는다**
4. 캡션을 그림 옆에 세워 싣는 조판(Springer)은 캡션 덩어리가 좁고 길면(높이 ≥ 폭×0.5)
   옆을 먼저 본다

**함정 세 가지**

- 문단의 **마지막 줄은 짧다**. 줄 단위로 '긴 줄'만 장벽 삼으면 그 꼬리가 그림 안에
  남는다 → 블록 단위로 본다
- **그림 안의 글자는 본문이 아니다**(축 라벨·패널 문자·범례). 본문보다 작거나,
  단 폭의 절반 미만이거나, 큰 조각 안에 있으면 본문으로 세지 않는다
- 합본 지면의 **옆 논문 그림**을 가져오면 안 된다. `boundary.py` 가 구간을 판정하고,
  `boundary.analyze` 가 실패하면 **한 장도 만들지 않는다**

로고·저널 마크·QR 은 크기(짧은 변 26pt 미만 / 넓이 1,300pt² 미만), **두 쪽 이상 같은
자리 반복**(같은 xref, 좌상단 ±6pt), 지면 55% 이상 배경 사각형으로 걸러낸다.

### 저장 — 다시 그리지 말고 원본을 꺼내라

여기서 화질이 갈린다. 영역을 잡았으면 **그 지면을 다시 그리는 것(render)** 과
**PDF 안의 원본 이미지를 그대로 꺼내는 것(native)** 두 길이 있다.

처음에는 전부 렌더였다. 그랬더니 원본이 1418×1145 인 사진도 170dpi 에서 816×600 이
된다 — **화소의 30% 만 남는다**(실측 6편 0.25~0.34). 이미 완성된 이미지가 파일로
박혀 있는데 다시 그릴 이유가 없다.

```
그림이 '내장 이미지 한 장' 인가?
  ├ 예 → fitz.Pixmap(doc, xref) 로 원본을 그대로 꺼낸다   ← 화질·속도 둘 다 이득
  └ 아니오 → 지면을 렌더한다(기존 방식)
```

**원본을 쓰면 안 되는 경우**(반드시 렌더로 되돌린다):

- 조각이 둘 이상 — 패널 a·b·c 를 합친 그림이라 한 장으로 안 된다
- 조각이 그림 영역 밖으로 걸쳐 있다 — 이 그림의 것이 아니다
- 원본과 놓인 자리의 **가로세로 비가 다르다** — 회전했거나 찌그러뜨려 앉혔다
- 원본이 놓인 크기에 비해 작다(96dpi 미만) — 늘려 앉힌 것이라 이득이 없다
- **사진 위에 얹힌 벡터 도형이 내용일 때** ← 가장 중요

마지막 항목이 함정이다. 임상 사진에는 병변을 가리키는 **화살표**가 벡터로 얹혀 있는
경우가 있다. 원본만 꺼내면 그 화살표가 사라진다 — 화질보다 큰 손실이다.
실측으로 갈랐다.

| 도형 | 실측 모양 | 판단 |
|---|---|---|
| 테두리 | 선 굵기 0.2pt, 그림 전체 크기 사각형, 항목 1개 | 버려도 됨 |
| 배경 | 채워진 그림 전체 크기 사각형, 항목 1개 | 버려도 됨 |
| **화살표·표식** | 28×54pt, 항목 6개 | **버리면 안 됨 → 렌더로** |

규칙: 얇은 선(짧은 변 ≤ 2.5pt)이거나, 항목 1개짜리로 그림의 70% 이상을 덮는
사각형이면 장식으로 보고 넘긴다. 그 밖은 내용일 수 있으므로 렌더로 되돌린다.

**실측 효과** (25편·43장): 19장(44%)이 원본 추출로 바뀌고 **총 화소 1.77배**.
편당 0.35초. 벡터 도형만으로 그려진 그림(forest plot·flow diagram)은 원본이 없으니
렌더밖에 답이 없다 — 다만 실제 논문에서는 그런 그림이 많지 않다.

렌더 쪽은 PNG 170dpi 가 기본. 한 장이 상한을 넘으면 DPI 를 96 까지 낮추고, 그래도
넘으면 그때만 JPEG(사진은 PNG 가 애초에 맞지 않는 형식이다).

`figures[].image` 에는 **늘 상대경로**를 담고 **기준점은 부르는 쪽이 정한다**
(`out_dir` 인자).

### PMC 에서 원본을 받아오는 선택지

검토했으나 **우선순위가 낮다**. 이 저장소 203편 중 PMCID 가 있는 것은 43편(21%)
뿐이고 그중 OA 패키지로 원본 이미지를 주는 것은 더 적다. JAAD·BJD·JDV 같은 주력
저널은 대부분 해당이 없다. 네트워크를 타니 느리기도 하다.
**내장 이미지 원본 추출이 전체 논문에 적용되고 더 빠르다.** PMC 는 그 다음이다.

> ⚠ **실제로 하루를 날린 함정.** 추출은 멀쩡히 되는데 화면에 안 뜬 적이 있다.
> figclip 이 정본 JSON 옆에 그림을 넣었는데 화면은 별도 그림 폴더를 보고 있었다.
> 저장 위치와 읽는 위치를 **한 곳에서 정하라.**

## 4-B. 화면 표현 — 뽑은 것을 어떻게 보여주는가

추출만 옮기면 절반이다. **읽는 경험**도 같이 가야 한다. 아래는 전부
`pubnexus/app.py` 한 파일에 들어 있다(CSS·JS 포함, 외부 CDN 0).

### 정본 → 화면

정본 JSON → `render.to_markdown()` → `md_to_html()` → WebView2.
Markdown 을 거치는 이유는 사람이 읽고 고칠 수 있는 중간물이 하나 필요해서다.
다만 **범용 마크다운 파서를 쓰지 않는다.** 의존성이 늘고, 정작 필요한 것
(표를 진짜 `<table>` 로, 인용을 옅게, 논문 종류를 회색 라벨로)은 어차피 직접 해야
한다. `render.to_markdown()` 이 내놓는 **좁은 방언만** 다루는 파서를 직접 둔다.

### 인용 `[15]` → 참고문헌 팝업

1. 렌더러가 본문 인용을 `<span class="cite">[15]</span>` 로 낸다
2. 참고문헌 항목마다 `id="ref-15"` 앵커를 붙인다
   (번호 → 앵커 id 규칙은 `render.ref_anchor_id()` 하나로 통일 — 어긋나면 안 된다)
3. 화면에서 `linkCites()` 가 **실제로 존재하는 앵커에만** `<a>` 를 건다.
   없는 번호는 그냥 글자로 둔다
4. 누르면 **아래로 뛰지 않고 그 자리에 카드**로 띄운다

> 아래로 스크롤해 버리면 **읽던 자리를 잃는다.** 논문을 읽다 인용을 확인하는
> 동작은 "잠깐 곁눈질"이지 "이동"이 아니다. 목록으로 가고 싶으면 카드 안의
> "목록에서 보기" 를 누른다. Esc·바깥 클릭·스크롤·창 크기 변경으로 닫고,
> 같은 인용을 다시 누르면 접힌다.

카드에는 **항목의 글만** 넣는다. 원본 DOM 을 그대로 복사하면 `id` 가 겹쳐
다음 클릭이 카드 안을 가리키게 된다.

### 본문 `Figure 1` → 그림 팝업

같은 방식이다. `<figure id="fig-1">` 앵커를 캡션 번호에서 만들고, 화면에서
TreeWalker 로 본문 텍스트의 `Figure 1`·`Fig. 2` 를 찾아 링크로 바꾼다.
**있는 그림에만** 건다. 캡션·제목·이미 링크인 곳은 건너뛴다.

누르면 카드에 **이미지와 캡션**이 함께 뜬다. 그림은 글이 아니라 그림을 봐야 한다.

### ⚠ 이미지에 width/height 를 반드시 넣어라

크기 없는 `<img>` 는 불러오기 전까지 높이가 **0** 이다. 그래서 인용을 눌러 자리를
계산해 놓아도, 그 뒤에 그림이 도착하면서 문서가 밀려 **엉뚱한 곳에 서 있게 된다.**
실제로 겪은 버그다. 팝업 위치 계산도 같은 함정에 걸린다.

PNG·JPEG 는 **헤더만 읽으면** 픽셀 크기를 알 수 있다(외부 라이브러리 불필요).
PNG 는 IHDR 의 16~24바이트, JPEG 는 SOF0~SOF15 세그먼트. 깨진 파일에서 우연히
SOF 처럼 보이는 바이트열에 속지 않게 **크기 범위 검증**(1~20000)을 붙인다.

### 그림 우클릭 — 복사·저장

`<img>` 가 가리키는 곳이 앱 저장소 안 내부 주소라 브라우저 기본 저장이 먹지 않는다.
직접 만든다.

- **복사** — `fetch` → blob → `navigator.clipboard.write`. 클립보드는 PNG 만 확실히
  받으므로 JPEG 는 캔버스로 옮겨 담는다. `localhost` 는 보안 컨텍스트라 클립보드
  API 가 동작한다
- **저장** — 파이썬에 파일 복사를 시킨다(네이티브 저장 대화상자).
  **경로 검사는 이미지를 흘려보내는 쪽과 같은 함수를 쓴다** — 한쪽만 느슨하면
  그쪽이 구멍이 된다(`../` 로 저장소 밖)

### 화면 구성

3분할 **1 : 2 : 2** — 왼쪽 파일목록 / 가운데 PDF 원본 / 오른쪽 추출 결과.
구분선을 끌어 조절하고, 두 번 누르면 기본 비율로 돌아온다.

- PDF 는 **모든 쪽을 이어 붙이고 보이는 곳만 그린다**(IntersectionObserver).
  이미지가 `<img src>` 로 나가야 브라우저가 지연 로딩·캐시·취소를 해준다 —
  큰 PDF 에서 멈추지 않는 유일한 방법이다
- 경로 표시는 **한 덩어리로 고르게**. 끝만 굵거나 진하면 시선이 끌려 읽는 흐름이
  끊긴다. 넘치면 **앞쪽**을 `…` 로 줄인다(뒤를 자르면 정작 어느 폴더인지 사라진다)
- 이력(뒤로/앞으로, Alt+←/→)을 둔다. 팝업으로 바꾼 뒤로도 그림 자리로 이동하는
  경로가 남아 있어서 필요하다

## 5. GROBID — 윈도우에서 돌리기

여기가 가장 많이 막히는 곳이다. 결론부터: **네이티브로 돈다. Docker 필요 없다.**
단 공식 배포본 그대로는 안 되고 **소스를 세 군데 고쳐 빌드**해야 한다.

### 왜 공식 배포본이 안 되나

윈도우에 번들된 `pdfalto` 는 **0.1** 이다(리눅스·맥은 0.5/0.6). kermitt2 가 윈도우
바이너리를 갱신하지 않는다. 이 0.1 은 GROBID 가 넘기는 인자 두 개를 **모른다**.

```
-noLineNumbers     ← 모름. 넘기면 변환이 시작도 못 하고 죽는다
-onlyGraphsCoord   ← 모름. 마찬가지
-blocks            ← 이것을 줘야 <TextBlock> 이 생긴다
```

그래서 무엇을 넣어도 늘 이렇게 끝난다:

```
[NO_BLOCKS] PDF parsing resulted in empty content
```

> ⚠ **틀린 진단을 기록에 남겼다가 하루를 더 썼다.** "GROBID 파서가 `<BLOCK>`/`<TOKEN>`
> 커스텀 포맷을 기대하는데 윈도우 pdfalto 는 표준 ALTO 를 내므로 불가능" — **틀렸다.**
> GROBID 0.9.0 의 `PDFALTOSaxHandler` 는 표준 ALTO(`Page`·`PrintSpace`·`TextBlock`·
> `TextLine`·`String`)를 읽는다. pdfalto 0.1 이 내는 바로 그 형식이다.
> 문제는 포맷이 아니라 **인자**였다. 같은 결론으로 돌아가지 말 것.

### 패치 세 곳 (GROBID 0.9.0 기준)

| 파일 | 고칠 것 |
|---|---|
| `build.gradle` (2곳) | Mac/Unix 외 플랫폼에서 `throw RuntimeException("Unsupported platform!")` → 윈도우 분기 추가 |
| `build.gradle` | `installDist { duplicatesStrategy = DuplicatesStrategy.EXCLUDE }` — 없으면 중복 jar(langdetect)에서 빌드가 멈춘다 |
| `grobid-core/.../DocumentSource.java` | 윈도우는 `-fullFontName -blocks`. `-noLineNumbers`·`-onlyGraphsCoord` 금지. 서버 모드의 `--timeout`·`--ulimit` 도 0.1 은 모르므로 **스레드 모드**로 보낸다 |

전 과정이 스크립트 하나에 들어 있다 — **그대로 실행하면 된다.**

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_grobid_windows.ps1
```

JDK 21 자동 설치(GROBID 0.9.0 이 `JavaLanguageVersion.of(21)` 선언) → 소스 내려받기
→ 패치 → `installDist` 까지 한다. 결과는 jar 183개 · 239MB.

**검증**: 영어 논문 6/6 성공(섹션 29 · 표 6 · 참고문헌 74 · 평균 2.4초/편).

### 서비스 기동 — 검은 창을 보이지 않게

`.bat` 으로 띄우면 `start` 가 새 콘솔을 연다. `grobid_service.py` 는 이렇게 한다.

- `javaw.exe`(콘솔을 만들지 않는 자바) + `CREATE_NO_WINDOW` + `DETACHED_PROCESS`
- 표준출력은 로그 파일로 (파이프가 차서 멎지 않게)
- 앱을 닫아도 서비스는 살아 있다

장시간 배치 중 서비스가 죽는다(실측 175편 중 2회, 246편 재추출 중 1회로 55편이
폴백으로 떨어졌다). **매번 생존을 확인하고 되살리는 장치가 반드시 필요하다**(최대 3회).

동시 처리는 **GROBID 호출만 2편으로 제한**한다. 한 편이 250~400MB 를 쓰고, 몰리면
죽는다. 편당 9.4초 → 3.9초.

### 사용자 PC 에 어떻게 심나 — 자동 설치

공식 배포본이 못 쓰니 **패치해 빌드한 결과물을 직접 배포**해야 한다(Apache-2.0 이라
재배포 가능).

```powershell
powershell -ExecutionPolicy Bypass -File tools\package_grobid_runtime.ps1
```

1,561MB → **zip 436MB** 로 줄인다. JDK 는 `jlink` 로 49MB(javaw.exe 포함 필수),
다른 OS 용 pdfalto·특허 모델·`*.hdf5`(DeLFT 용) 제거. CRF 모델(`.wapiti` 437MB)은
그대로 둔다 — 이게 본체다.

`grobid_service.py` 가 **위치를 고정하지 않고** 이 순서로 처리한다.

1. 8070 에 살아 있나 → 그대로 쓴다
2. 이 PC 어딘가에 깔려 있나 — `GROBID_ROOT` 환경변수 → 앱 저장소 → `C:\grobid`
   → 다른 드라이브 → exe 옆
3. 없으면 Releases 에서 내려받아 `%LOCALAPPDATA%` 에 설치 (**관리자 권한 불필요**)

실측: 아무것도 없는 상태에서 **82초**(내려받기 → 압축해제 → 기동 → 응답).
받는 파일이 공개돼 있어야 한다 — 비공개 저장소 릴리스는 인증 없이 404 다.

## 6. 윈도우에서 반드시 밟는 지뢰 두 개

### (1) cp949 인코딩 — 로그 한 줄이 프로그램을 죽인다

한글 윈도우 콘솔은 cp949 다. **cp949 에는 em대시(`—`, U+2014)가 없다.**
(있는 것은 `―` U+2015 다.) 로그 문구에 `—` 가 섞여 있으면 그 자리에서
`UnicodeEncodeError` 가 난다. 그것이 **except 블록 안이거나 워커 스레드 안이면
뒤따르는 상태 전환이 통째로 사라진다.**

실제로 두 번 당했다.

- 설정 파일을 못 찾은 예외를 안내하다가 **예외 처리 중 다시 예외** → 앱이 통째로 종료
- "분석 엔진 없이 진행 — PyMuPDF 폴백" 을 찍다가 스레드가 죽어, 바로 다음 줄의
  상태 전환이 실행되지 않음 → 화면이 **"준비 중"에서 영원히 멈춤**

```python
def log(msg: str):
    """로그 한 줄 때문에 프로그램이 죽는 일은 없어야 한다."""
    try:
        print(msg, file=sys.stderr, flush=True)
    except UnicodeEncodeError:
        enc = getattr(sys.stderr, "encoding", None) or "ascii"
        try:
            print(msg.encode(enc, "replace").decode(enc, "replace"),
                  file=sys.stderr, flush=True)
        except Exception:
            pass
    except Exception:      # exe(windowed) 는 stderr 자체가 없다
        pass
```

`sys.stdout.reconfigure(encoding="utf-8")` 만 믿으면 안 된다. windowed exe 에서는
그 호출이 조용히 실패한다.

같은 이유로 **PowerShell 스크립트(.ps1)는 UTF-8 BOM 으로 저장**해야 한다.
PowerShell 5.1 은 BOM 없는 UTF-8 을 ANSI 로 읽어 한글 주석이 깨지고, 깨진 바이트가
따옴표를 먹어 **파싱 오류**를 낸다.

### (2) 백신 오탐 — PyInstaller onefile

Defender 가 배포용 exe 를 **`Trojan:Win32/Wacatac.H!ml`** 로 잡고 **지웠다**.
`!ml` 은 서명 일치가 아니라 머신러닝 추정이다. onefile 은 실행할 때 자기 안을
임시폴더에 풀어 돌리는데, 그 동작이 악성코드와 구조가 같아 늘 걸린다.

**해결**: `--onefile` → `--onedir` + Inno Setup 설치프로그램(`tools/installer.iss`).
받는 쪽이 받는 것은 여전히 파일 하나다. Defender 스캔 통과 확인
(설치프로그램·프로그램 exe 모두 `found no threats`).

설치프로그램은 `PrivilegesRequired=lowest` 로 둔다 — 병원 PC 처럼 권한이 막힌 곳에서도
깔린다. 지울 때 사용자가 뽑아 둔 정본·그림은 **남긴다**.

그 밖에 PyInstaller 관련:

- 빌드 폴더는 **리포와 같은 드라이브**에 둘 것. 다르면
  `ValueError: path is on mount 'D:', start on mount 'C:'` 로 죽는다
- Dropbox 안에서 빌드하면 동기화가 파일을 잠가 무작위로 실패한다 → Dropbox 밖에서
- `torch`·`transformers`·`onnxruntime`·`lancedb`·`scipy`·`pandas` 는
  `--exclude-module`. 안 하면 exe 가 수백 MB 로 붇는다
- pywebview 는 `clr_loader`·`pythonnet`·`bottle` 을 hidden import 로 명시하고
  `--collect-all webview`

## 9. 검증 — 고쳤다고 말하기 전에

**규칙 기반 탐지 ≠ 검증.** 미리 생각해 넣은 결함만 잡힌다. 실제로 167편을 눈으로
읽어 대조했을 때 규칙이 놓친 결함이 대량으로 나왔다(판정 perfect 15 · minor 37 ·
broken 113, 결함 798건).

지켜야 할 것:

- **수리 전/후를 같은 잣대로 재라.** 한쪽만 새 기준으로 재면 개선처럼 보인다
- **모든 진입 경로를 실제로 돌려라.** 필드 개명 한 번에 읽기 경로 3개
  (`grobid_client`·`pmc_xml`·`pdf_fallback`)가 동시에 죽은 적이 있다. 캐시된 TEI 로만
  확인해서 폴백 경로를 한 번도 안 돌렸다. **GROBID 를 끈 상태로도 돌려 보라**
- **지표를 낮추는 데 최적화하지 마라.** 미분류 비율을 낮추려다 `Primer`→intro
  오분류를 성과로 착각했다. 틀린 라벨보다 정직한 `other` 가 낫다
- **고쳐서 나빠지는 경로를 경계하라.** 문단 병합 33건 중 14건이 완결 문장 뒤에 엉뚱한
  조각을 붙였고, 붙고 나면 대문자로 시작해 **탐지기에 다시 안 잡혔다**(결함이 숨는다)
