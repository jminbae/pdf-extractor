# 범용 Markdown 자료 수집기: 서비스 벤치마킹과 UX 제안

조사일: 2026-10-23 · 목적: AI 입력·위키용 자료 수집 앱의 기능 우선순위 결정

> **최신 범위:** 이 문서는 서비스 비교와 초기 기능 후보입니다. 사용자 피드백을 반영한 [최신 간소화안](./2026-10-23-simplified-scope.md)을 구현 기준으로 사용합니다. 셀별 원본 이동·감시 폴더·자동 개정판·유료 API·자동 의미 태깅은 초기 범위에서 제외 또는 보류했습니다.

공식 제품 문서로 기능을 확인한 조사입니다. 로그인 평가·문서 업로드·유료 API 사용·실측 품질 비교는 하지 않았습니다. 아래의 벤치마킹 항목과 우리 앱 기능은 제안이며, 실제 경쟁 제품의 사용성을 평가한 점수가 아닙니다. 구현 계획은 [통합 계획서](./2026-10-23-document-markdown-plan.md)에 있습니다.

## 1. 유사 제품은 두 부류를 함께 비교

직접 비교 대상은 문서를 AI가 읽을 수 있는 구조로 바꾸는 서비스입니다. 자료 수집·정리·검수 경험은 문서 관리 도구와 Markdown 도구에서도 참고할 수 있습니다. 어느 한 제품의 기능 전체를 복제하기보다 필요한 책임을 구분합니다.

| 대상 | 공식 자료에서 확인한 기능 | 벤치마킹할 부분 | 우리 앱에 반영할 방향 |
|---|---|---|---|
| [LlamaParse](https://developers.llamaindex.ai/llamaparse/parse/) | 문서에서 Markdown/JSON 등 생성, 표·도표·레이아웃/위치 정보·스프레드시트 관련 기능 | 표와 도표 출력, 설정별 품질 차이, 원문 위치, 비동기 결과 접근 | 원문 전체와 AI용 구조·블록 출처를 함께 제공 |

| [Paperless-ngx](https://docs.paperless-ngx.com/usage/) | 감시 폴더·웹 업로드·메일 수집·작업 규칙·중복 관리 | 폴더에 넣어 자동 처리하는 경험, 문서 목록·상태·태그 | 감시 폴더·중복 연결·검수 대기열. 원본 처리는 읽기 전용이 기본 |
| [Obsidian Web Clipper](https://obsidian.md/clipper) | 웹 내용/하이라이트 저장, 템플릿과 사이트별 규칙 | 파일 외 정보 수집, 짧은 저장 동작, 메타데이터 템플릿 | URL·선택 영역·전체 본문 수집, 출처와 태그 자동 제안 |
| [Firecrawl](https://www.firecrawl.dev/scrape) | 웹에서 Markdown·HTML·링크·스크린샷·메타데이터 반환 | 웹 원본과 정리한 본문을 함께 보관하는 흐름 | 웹 adapter의 출력 계약 참고, 로컬 본문 추출과 선택 API를 교체 가능하게 구성 |

위 링크는 기능의 1차 출처입니다. 업체가 주장하는 정확도·속도·처리량을 검증된 제품 순위로 옮기지 않았습니다. 사용 플랜·지역·배포 방식별 기능과 데이터 처리 조건은 도입 시 다시 확인합니다. 가격 비교는 동일 표본의 실제 처리량·재시도·선택 기능을 고정한 뒤 해야 공정합니다.

Paperless-ngx는 consumption 폴더에서 처리한 파일을 내부 저장소로 옮기는 동작을 문서화합니다. 이 앱에서는 원본을 지키는 사용 흐름이 중요하므로 해당 동작을 그대로 복제하지 않습니다. [공식 사용 안내](https://docs.paperless-ngx.com/usage/)

## 2. 우리의 제품 방향

권장하는 핵심 경험은 **“자료를 넣으면, AI와 위키에 바로 활용할 수 있는 Markdown 묶음이 생기고, 부족한 부분은 원본과 함께 확인할 수 있다”**입니다.

차별화 가설은 다음 조합입니다. 시장에 아무도 없다는 확정 주장이 아니라, 위 제품 자료에서 배운 내용을 사용자 목표에 맞게 묶은 제안입니다.

- 한국어·HWP/HWPX·Office와 장문 PDF를 한 수집 흐름에서 처리.
- 로컬 우선, 원본 보존, 범위가 분명한 외부 처리 선택.
- 표·숫자·각주의 원문 위치와 추출 실패를 드러내는 검수.
- 대문서가 중단되어도 이어서 처리하고, 실패한 쪽/표만 다시 추출.
- 특정 위키·AI 서비스에 종속되지 않는 MD·자산·메타데이터 출력.

채팅·검색·위키 생성은 이 기반을 쓰는 후속 기능입니다. 추출 앱 안에 모든 지식 관리 기능을 먼저 넣으면 핵심 품질과 안정성의 검증 범위가 커집니다. 초기 제품은 결과를 다른 도구로 가져가는 과정까지 잘 마무리하는 데 집중하는 편이 적합합니다.

## 3. 기능 우선순위

| 우선순위 | 기능 | 사용자에게 생기는 효과 | 확인 방법 |
|---|---|---|---|
| P0 | 표 구조·본문 혼입 개선 | 숫자를 다시 손으로 표로 옮기는 일 감소 | 셀·병합·각주·본문 중복 대조 |
| P0 | 문단·표·그림의 원본 위치 연결 | 결과를 믿어도 되는지 바로 확인 | 셀/문단 클릭 후 정확한 원본 위치 열림 |
| P0 | 부분 성공·미지원·검수 필요 표시 | 누락을 완료로 오인하지 않음 | 실패 fixture의 상태와 export 경고 확인 |
| P0 | 작업 큐·중단/재개·쪽별 격리 | 책 한 권 때문에 처음부터 재시작하지 않음 | 강제 종료·재부팅·timeout 후 재개 |
| P0 | 전체 MD+자산 패키지 | AI·위키에 파일을 가져다 쓰기 쉬움 | 외부 연결 없이 이미지·표·링크 열기 |
| P1 | 감시 폴더·다중 드래그·하위 폴더 선택 | 반복 수집 동작 감소 | 복사 중/이름 변경/중복/여러 문서 흐름 |
| P1 | 원본·결과 비교와 해당 표만 재추출 | 수리 범위가 작고 결과 비교가 쉬움 | 원문 고정 상태에서 후보 결과 전후 비교 |
| P1 | 장/절 단위 MD·목차·파일 manifest | 책을 AI 문맥과 위키에 맞게 나눌 수 있음 | 순서·연속 표·각주·상대경로 확인 |

| P1 | 출력 템플릿·호환성 미리보기 | 복잡한 표가 대상 도구에서 깨지는 일 감소 | 일반 MD·HTML 허용/차단 profile별 열기 |
| P1 | 로컬/외부 처리 범위·예상 비용 표시 | 어디서 처리되는지, 재시도 비용을 알 수 있음 | 페이지 선택과 외부 실행 범위/상한 일치 |
| P2 | 웹 URL·선택 클립·스크린샷·메일 첨부 수집 | 문서 파일 밖의 정보를 같은 자료함으로 수집 | 출처·자산·첨부 관계 유지 |
| P2 | 제목·태그·카테고리 제안 | 파일 정리 부담 감소 | 제안 수정과 다중 일괄 편집 |
| P2 | 위키 연결·목차·색인 생성 | 자료 간 탐색 개선 | 링크가 실제 파일·블록을 가리키는지 검사 |
| 후속 | 근거가 연결된 요약·위키 초안 | 긴 자료를 탐색할 입구 제공 | 원문과 생성문 분리, 각 주장 출처 확인 |

P0/P1/P2는 구현 권고 순서이며 완성된 기능이 아닙니다. 웹 수집이 첫 사용의 큰 비중이라면 파일 확장과 독립된 adapter 실험으로 P1에 당길 수 있습니다.

## 4. 첫 사용부터 export까지의 UX

### 자료 추가

초기 화면의 주 동작은 `파일·폴더 추가`, `URL/텍스트 붙여넣기` 정도로 단순하게 둡니다. 파일 선택 뒤 형식, 쪽수/슬라이드 수, 스캔 여부, 예상 처리 경로와 미지원 항목을 먼저 보여 줍니다. 엔진 선택·DPI·OCR 옵션은 기본 흐름에서 숨기고 필요할 때 상세 설정에서 바꿉니다.

폴더 단위 추가에는 하위 폴더 포함과 제외 범위를 제시합니다. 이미 있는 동일 파일은 기존 자료로 연결할 수 있게 하며, 개정판 후보를 단순 중복과 구분합니다. 모르는 형식은 조용히 건너뛰지 않고 목록에 남깁니다.

### 변환 중

프로젝트 목록에는 문서마다 `대기`, `쪽 추출`, `표 검사`, `조립`, `내보내기` 상태를 보여 줍니다. 책은 `총 842쪽 중 216쪽 처리 / 표 3개 검수 필요`처럼 실제 완료 단위를 표시하는 것이 유용합니다. 이 숫자는 화면 문구 예시입니다. 측정하지 않은 완료 시간을 정확한 예측처럼 표시하지 않습니다.

대기 중인 문서의 우선순위를 바꾸고, 선택 문서만 취소·재개할 수 있게 합니다. 완료된 부분을 보면서 다음 페이지 처리가 계속되도록 하되, 임시 미리보기에는 아직 작업 중임을 표시합니다. 앱을 닫거나 PC가 재시작되어도 원장에서 작업을 복구합니다.

### 결과 검수

기존 3분할 화면을 살립니다. 왼쪽은 문서/장/검수 항목, 가운데는 원본, 오른쪽은 Markdown 결과입니다. 작은 화면에서는 원본/결과 탭으로 바꾸고 목록을 접습니다.

- **원본 위치를 유지합니다.** 표 재추출이나 문서 선택으로 읽던 쪽을 불필요하게 초기화하지 않습니다.
- **클릭으로 대응 위치를 찾습니다.** 결과 문단·셀을 클릭하면 원본 영역을 강조하고, 원본에서 선택한 표의 결과도 열 수 있게 합니다.
- **스크롤 동기화는 선택 기능입니다.** 책의 읽기 순서와 재배치된 표 때문에 무조건 동기화하면 이동이 튈 수 있습니다.
- **검수 대기열을 둡니다.** 빈 표·숫자 충돌·출처 불명·미지원 객체를 우선순위로 보여 주고 항목별로 해결합니다.
- **한 표만 다시 추출합니다.** 기존 결과와 후보 결과를 비교한 뒤 적용하고 되돌릴 수 있게 합니다.
- **수동 편집을 보존합니다.** 원문 교정, 표 구조 수정, 사용자의 메모와 자동 추출을 구분하고 재실행으로 덮어쓰지 않습니다.

본문의 작은 종합 점수 하나보다 `표 12개 중 10개 구조화, 2개 검수 필요`처럼 무엇이 빠졌는지 보여 주는 상태가 판단에 도움이 됩니다. 모델 confidence를 사람이 검수했다는 뜻으로 사용하지 않습니다.

### 내보내기

사용자가 고를 것은 `전체 자료`, `선택 장/쪽`, `표 데이터`와 `단일 MD`, `MD+자산 묶음`, `장별 MD` 정도로 제한합니다. AI용 JSONL 청크·스키마 설정은 고급 옵션입니다.

복잡 표가 HTML을 필요로 할 때 호환성 미리보기를 제공합니다. 출력 패키지에서 자산 누락·깨진 상대경로·동명 파일 충돌을 검사하고, 성공하면 출력 폴더를 바로 열 수 있게 합니다. 기존 결과가 있을 때 자동 덮어쓰기보다 revision과 차이를 보여 줍니다.

## 5. 실제 벤치마크 실행 방법

1. 같은 입력과 버전을 사용합니다. 디지털 PDF·스캔·HWP·Office·긴 책·복잡표를 나누고 문서군별 결과를 비교합니다.
2. 비교 도구에 동일한 보존 목표를 줍니다. 전체 본문 추출과 특정 필드만 추출하는 서비스 결과를 같은 완성도로 비교하지 않습니다.
3. 품질은 누락·표 구조·숫자·본문 오염·원본 위치를 따로 측정합니다. 속도는 대기·업로드·변환·결과 다운로드를 분리합니다.
4. 재시도와 사람이 수리한 시간도 기록합니다. 한 번의 API 호출 가격만으로 실제 작업 비용을 판단하지 않습니다.
5. 로컬 도구는 새 Windows 설치와 CPU/GPU 환경을 구분합니다. 서비스 비교에는 공개·합성 자료부터 사용하며, 실제 내부 문서는 외부 전송 범위가 정해지기 전 올리지 않습니다.
6. 긴 책은 시작·중간·끝을 모두 검사합니다. 쪽 제한·기본 범위 때문에 앞부분만 추출한 결과를 전체 성공으로 세지 않습니다.
7. AI 활용 시험에는 고정 질문을 사용합니다. 표의 수치·조건·각주와 책의 원본 쪽을 맞추는지 평가합니다. 답변이 자연스러운지와 근거가 정확한지는 별도 점수로 둡니다.
8. UX는 실제 사용자가 수행하는 과제로 측정합니다. 첫 MD export까지 시간, 누락 표 발견 시간, 한 표 재추출 시간, 중단 후 재개에 필요한 동작 수, 출력 파일 찾기 성공 여부를 봅니다.

우선 비교 조합은 **기존 PubNexus + Docling + rHWP + 독립 OCR/표 경로**입니다. 외부 서비스는 이 조합으로 부족한 한국어·복잡표·수식 사례의 참고 품질을 확인하는 비교군으로 추가할 수 있습니다. 어느 서비스가 가장 정확한지는 현재 조사만으로 순위를 매기지 않습니다.

## 6. 먼저 만들지 않아도 되는 기능

초기에는 앱 안의 범용 챗봇, 자동 지식 그래프, 모든 클라우드 서비스 동기화, 완전한 HWP/Office 편집기, 자동 위키 공개를 미룹니다. 출처·추출 품질·장문 안정성·MD 이동성이 먼저 확보되면 이 기능들을 독립적으로 붙일 수 있습니다.

사용자가 처음 확인할 구체적인 성과는 **현재 실패하는 표를 정확하게 분리하고, 긴 PDF를 중단 후 이어서 처리해, 다른 AI·위키 도구에서 열리는 MD 묶음을 만드는 것**입니다.
