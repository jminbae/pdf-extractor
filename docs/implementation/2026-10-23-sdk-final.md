# 공개 SDK 우선 구현과 최종 검증

## 구현 원칙

사용자 요청대로 기존 공개 방법을 먼저 조사·실측하고 앱을 연결했습니다. 일반 PDF의 자체 reading_flow 코드는 제품에서 제거했습니다. [ENGINE_POLICY](./ENGINE_POLICY.md)를 따릅니다.

- 정상 논문: 기존 GROBID/JATS와 보존 검사 유지.
- 일반 PDF: PyMuPDF 2.0 공식 Markdown/좌표 API를 격리 frozen worker에서 사용. 메인 앱은 기존 PyMuPDF 1.28 유지.
- HWP/HWPX: rHWP CLI/DocLang, HOP 앱 의존 없음.
- Office: python-docx/python-pptx/openpyxl, 추가 형식은 Pandoc/MarkItDown, 어려운 표는 선택 Docling 보완.
- 앱 고유 코드: 작업·취소·진행 표시·자동 저장·상대 자산·원본 대조·오류 격리. SDK 본문·읽기 순서·표를 다시 조립하지 않음.

## 짧은 장 제목 복구

실제 책에서 SDK header/footer 제외 옵션이 짧은 제목13쪽을 함께 제외하는 것을 발견했습니다. 본문 알고리즘을 새로 만드는 대신 공개 옵션으로 해당 쪽만 재시도합니다.

1. 원문 텍스트가 있지만 SDK Markdown이 빈 쪽을 확인합니다.
2. 공식 header=True/footer=False 결과가 있으면 해당 SDK chunk를 그대로 사용합니다.
3. 여전히 빈 쪽만 header=True/footer=True로 재시도합니다.
4. SDK가 page-footer로 분류했고 실제 PDF label/물리 쪽번호와 일치하는 숫자만 pagination_only로 기록합니다. 숫자본문2026을 보존하는 반례 시험을 포함합니다.

각 시도의 옵션·전후 SHA를 recovery_per_page에 기록합니다. 기존 SDK page chunk 결합과 공식 위치 범위를 재사용합니다. engine identity는 pymupdf-2.0-adapter-2입니다.
