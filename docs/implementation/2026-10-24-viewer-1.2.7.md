# 1.2.7 — 빠른 문서 뷰어

사용자의 최신 우선순위는 문서를 빠르게 읽는 것입니다. Markdown 추출은 상단의 직접 버튼으로
제공하는 보조 기능입니다. 기본 목록에는 저장 완료·대기·추출 품질을 표시하지 않습니다.

## 화면과 동작

- 폴더 트리 / 파일 리스트·썸네일 / 원본 미리보기의 3패널입니다. 한 번 선택하면 원본이 열리고,
  두 번 누르면 넓혀 읽습니다. MD 보기로 같은 패널을 전환합니다.
- 익숙한 위치 표시·현재 폴더 검색·키보드 파일 이동·마우스 뒤로/앞으로를 제공합니다.
  이력 복원은 문서 위치와 선택한 표시 방식을 함께 보존합니다.
- 상단 `MD 추출`·`MD 보기`, 원본 보기·확대·닫기를 직접 누릅니다. TXT·MD는 추가 추출을 하지 않습니다.
- PDF·PPTX·HWP/HWPX는 연속 스크롤하며 화면과 인접 쪽부터 준비합니다. DOCX 등은 본문 창,
  XLSX·ODS는 셀 창을 읽습니다. 전체 변환이나 MD 추출을 기다리지 않습니다.
- 문서마다 로컬 검색·Ctrl+휠 배율·라이트/다크 테마를 사용합니다. 원본 파일은 수정하지 않습니다.

## 검증된 라이브러리 재사용

PDF는 PyMuPDF, PPTX는 고정한 공개 브라우저 렌더러, DOCX는 python-docx, XLSX는 공식
openpyxl ExcelReader/WorkSheetParser를 사용합니다. dimension 없는 XLSX의 전체 XML 선행
읽기를 없앴으며 원래 수식과 저장된 값을 함께 보존합니다. 파일을 다시 계산하지 않습니다.

HWP/HWPX는 동봉한 rHWP의 공식 render-tree로 쪽 크기를 얻고, 선택 쪽만 export-png로
표시하며 export-text의 정확한 쪽 번호로 검색합니다. Office나 한글 설치가 필요하지 않습니다.
RTF는 striprtf 0.0.34의 공개 파서를 사용합니다. HTML·EML·MBOX·ODF·EPUB는 기존 문서
어댑터를 재사용합니다. HTML의 외부·인접 이미지 파일은 자동으로 열지 않습니다.

기존 MD는 Markdown-it으로 읽고 원본 줄 번호를 보존합니다. 실제 상대 경로 하위의 검증된
래스터 이미지만 표시합니다. 스크립트·원격 이미지·상위 경로 참조는 실행하거나 불러오지 않습니다.

## 응답성과 자료 보존

이전 선택의 미리보기는 취소하고 최신 선택을 우선합니다. 요청은 viewer 세대와 원본 경로에
묶이며 폴더 변경으로 같은 목록 번호가 다른 파일을 가리키면 거절합니다. 메타데이터·그림 캐시는
개수와 바이트 한도를 가집니다. PDF 캐시에서 밀려난 문서로 돌아오면 원본 핸들을 다시 엽니다.

추출은 기존 독립 프로세스 경로를 유지합니다. 뷰어 이동·검색·닫기는 추출 완료를 기다리지 않습니다.
사용자 원본·기존 Markdown·설정·이전 배포물은 별도 백업 및 해시 대조 대상으로 보존합니다.
설치 식별자·업데이트 자산 이름·기본 출력 폴더는 기존 값과 호환됩니다.

## 측정 범위와 남은 제약

개발 App 브라우저에서 실제 70MB·42장 PPTX의 첫 내용은 930ms, 현재 화면 그림의 디코드는
943ms였습니다. 실제 13쪽 PDF는 133ms, 합성 DOCX는 230ms, TXT는 64ms였습니다.
396쪽 PDF의 백엔드 메타데이터는 첫 119ms, 재열기는 0.19~0.53ms였습니다.
12쪽 HWPX는 메타데이터와 첫 PNG 합계 667ms, 같은 PNG 재요청은 12ms였습니다.
이는 해당 파일·환경의 개발 측정이며 모든 문서의 OS 화면 표시 시간을 보증하지 않습니다.

DOCX 내용 보기는 원본의 모든 조판·도형·수식을 재현하지 않습니다. 명시적 PDF 대체 표시는
호환되는 로컬 변환 엔진이 필요할 수 있습니다. 구형 XLS·MSG와 일부 외부 형식도 별도 도구가
필요할 수 있습니다. 이미지 안의 복잡한 수식 OCR은 아직 일반적으로 정확하다고 검증하지 못했습니다.
추출의 이 한계는 빠른 원본 뷰어의 성공과 구분하며 실패한 정보를 정상으로 꾸미지 않습니다.

배포 시 최종 소스·실행파일·설치파일·모델·고지·WebView2 실제 실행과 원본 무변경을 별도로 검증합니다.
최종 배포와 설치 증거는 HANDOFF의 1.2.7 절에 기록합니다.

배포 후보는 Python 413개·UI 33개 및 실제 동결 실행파일의 PDF13쪽/스캔OCR/PPTX71장/native6형식
검사를 통과했습니다. 71장 첫 디코드는1183ms였으며 실제 소유iframe의 Ctrl+F·Esc, 검색 위치,
원본/MD 확대·전환·독립 추출 프로세스·원본 보존을 확인했습니다. 숨김 테스트에서 parent와 child의
포커스를 섞었던 이전 실패는 보존하고 하네스의 소유child focus/input/reset 경계만 보완했습니다.
전체 자산 감사는 main51/worker4 모듈·모델·34/21개 의존성 고지·업스트림 striprtf 원본 코드·metadata와
각 실제 QA의 실행파일/외부자산 해시 결합을 확인했습니다. 강제reload 때의 오래된 list_folders callback
예외 각1건은 PDF/scan 기능 성공과 별도 알려진 로그 한계로 남깁니다.
