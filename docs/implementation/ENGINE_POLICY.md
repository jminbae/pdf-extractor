# 공개 도구 우선 원칙

사용자 확정: “항상 오픈된 방법, 이미 검증된 표준 방법을 먼저 찾아서 적용하고, 우리 특이적인 부분만 우리 방법을 찾자.”

1. 새 추출 기능은 공식 문서·공개 구현을 먼저 찾습니다. 지원 여부를 추측하지 않고 버전·옵션·라이선스를 확인합니다.
2. 실제 입력과 합성 정답으로 후보를 비교한 후 재사용합니다. 유명함이나 벤치마크 수치만으로 모든 문서의 정확성을 단정하지 않습니다.
3. 라이브러리가 제공하는 문단·읽기 순서·표·그림·Markdown을 앱에서 다시 만드는 알고리즘으로 대체하지 않습니다.
4. 직접 구현하는 부분은 작업 큐·취소·오류 격리·자동 저장·자산 경로·원본 대조·앱 상태 연결과 검증된 도구의 구체적인 빈틈입니다.
5. SDK가 해결하지 못하는 문제는 한계로 남겨 표시합니다. 임의 교정으로 원문 의미를 바꾸지 않습니다.

## 이번 PDF 적용

- 모든 새 PDF·다시 추출하는 PDF는 같은 공식 [PyMuPDF Document.to_markdown](https://pymupdf.readthedocs.io/en/latest/document.html#Document.to_markdown) 엔진으로 시작합니다. 책/논문이라는 의미 분류로 경로를 나누지 않고 다단·표·그림·스캔 구조를 처리합니다. DOI·서지정보 조회·GROBID는 데스크톱 본문 추출의 선행 조건이 아닙니다. 기존에 저장한 정상 결과는 다시 추출하기 전까지 보존합니다.
- 문서 추출 전체를 GUI와 별도 프로세스로 실행하며, 공식 SDK는 그 안의 별도 2.0 런타임입니다. 메인 앱의 PyMuPDF 1.28은 원본 표시 등에 사용합니다. [PyMuPDF 공식 multiprocessing 지침](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html)에 따라 스레드만 나누어 무거운 PDF 연산을 GUI 프로세스와 공유하지 않습니다.
- 최초 SDK Markdown/chunk를 별도 raw 자료로 보존합니다. 최종 Markdown은 공식 표 내보내기와 아래의 제한된 한글 경계 보정만 반영하고, 단계별 입력·변경 근거·문자 범위를 유지합니다. 원본 대조는 SDK의 쪽·좌표와 보정된 범위를 사용합니다.
- SDK가 짧은 제목을 제외해 결과가 빈 쪽은 공식 header/footer 옵션으로 해당 쪽만 재시도하고 SDK chunk를 사용합니다. 실제 책 제목13개를 복구했습니다.
- 병합 표는 공개 `Page.find_tables(refine=True)`와 `Table.to_html()`을 사용합니다. 기존 SDK 표 위치에 유일하게 대응하고 행·열·셀 값·기호·숫자 경계가 일치하는 경우에만 HTML 표로 대체합니다. 단순 표는 그대로 유지합니다.
- 한글 물리줄 경계는 공개 Kiwi.glue/space/analyze가 일치하고 원문 좌표와 글자가 대응하는 경우에만 공백을 보정합니다. 쪽 경계는 동일 어휘의 원문 증거와 연속 문단 기하 조건도 요구하며, 그림·캡션은 내용과 순서를 보존해 연결된 문단 뒤에 둡니다. 원문 문자 치환·새 문장 생성은 하지 않습니다.
- 텍스트 없는 쪽은 공개 Pixmap·벡터·이미지 API로 단색 배경을 입증하거나 실제 로컬 Tesseract를 재실행합니다. OCR 실패를 빈 쪽의 증거로 삼지 않습니다.
- 그림은 안전하게 원본과 완전 대응하는 경우 원본 바이트를 재사용합니다. 클리핑·투명도·겹침 등으로 대응이 불명확하면 공식 SDK의 300dpi crop을 사용합니다. 엔진별 새 자산 경로로 기존 이미지 덮어쓰기를 막습니다.
- 화면 표시는 markdown-it-py를 재사용합니다. 문서의 실행 가능한 HTML은 표시하지 않습니다.
- 기존 native/OCR 결과는 SDK 실패 시 보존합니다. 원본 해시 변경·자산 충돌·취소는 성공으로 낮추지 않습니다.
- 본문 보존 검사는 공식 MarkdownIt와 lxml로 얻은 표시 텍스트를 비교합니다. 표의 `<br>` 같은 서식 문자열을 본문 문자로 비교하지 않으며, 실제 전체 쪽 누락을 거절하는 기준은 유지합니다.
- Docling은 비교·어려운 표 보완에 사용합니다. SDK Markdown을 Docling 결과와 임의 혼합하지 않습니다.
- 자체 `reading_flow` 구현은 제품 경로에서 제거했습니다. 비교 소스·결과는 DevCache에 보존했습니다.

## 문서별 프로세스와 자원 대기열

문서 하나마다 소유한 새 프로세스를 실행합니다. Python 표준 ThreadPoolExecutor는
프로세스 감시만 담당하고, 무거운 추출은 GUI 인터프리터에서 실행하지 않습니다.
작업 중 새 요청도 대기열에 추가합니다. 내용 SHA가 같은 문서는 공유 캐시 충돌을
피하도록 순서대로 처리하며, 다른 문서는 독립적으로 실행합니다. 출력 폴더의
파일명 선택부터 manifest 저장까지는 표준 OS 파일 잠금으로 보호합니다.

공개 psutil로 소유한 작업의 자식 프로세스와 시스템 여유를 측정합니다. 물리 CPU
절반을 기본 동시 한도로 사용하되 상한은 10개입니다. 신규 실행 시 앱 메모리 예상
사용량은 전체 RAM의 50% 이내, 시스템 예비 메모리는 15% 또는 2GiB 중 큰 값으로
잡습니다. 시스템 CPU가 90% 이상이면 새 실행을 기다립니다. PDF는 처음 2GiB,
Office는 512MiB, 텍스트는 128MiB를 예약하고 관측한 최대 사용량에 따라 늘립니다.

이 수치는 **새 작업을 시작하는 기준**이며 실행 중인 문서에 강제로 적용하는 메모리
제한은 아닙니다. 자원 부족 시 새 작업을 보류하고 기존 작업을 계속 감시합니다.
초기 예약조차 충족하지 못하는 저사양 PC는 예상 잔여 512MiB 이상일 때 한 개만
허용합니다. 화면에 실행·대기 수, 실제 메모리·예산·CPU와 대기 사유를 표시합니다.

## 검증 범위와 한계

396쪽 책에서 발견한 `통 해`, `멜라닌색`/`소가`는 실제 SDK+Kiwi로 보정하고 사진3개와 캡션1개 보존을 확인했습니다. 표본 성공을 다른 모든 PDF의 정확성으로 일반화하지 않습니다.

공개 [Kiwi.glue](https://bab2min.github.io/kiwipiepy/v0.23.2/kr/#Kiwi.glue) 단독 적용은 정상 어절을 잘못 붙이는 반례 때문에 채택하지 않았습니다. 물리줄 증거와 space/analyze 검증을 추가한 좁은 경로에서는 `보호하며 일반적으로`를 그대로 보존하는 실제 모델 반례도 검사합니다. 표·참고문헌·캡션·코드·OCR 블록은 이 한글 보정 대상에서 제외합니다.

SDK·앱 단위 시험, 전체 책 실행, 실제 frozen worker·설치 프로그램의 검증 상태는 HANDOFF와 검증 기록에 구분해 남깁니다.
