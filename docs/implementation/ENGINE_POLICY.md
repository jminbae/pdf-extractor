# 공개 도구 우선 원칙

사용자 확정: “항상 오픈된 방법, 이미 검증된 표준 방법을 먼저 찾아서 적용하고, 우리 특이적인 부분만 우리 방법을 찾자.”

1. 새 추출 기능은 공식 문서·공개 구현을 먼저 찾습니다. 지원 여부를 추측하지 않고 버전·옵션·라이선스를 확인합니다.
2. 실제 입력과 합성 정답으로 후보를 비교한 후 재사용합니다. 유명함이나 벤치마크 수치만으로 모든 문서의 정확성을 단정하지 않습니다.
3. 라이브러리가 제공하는 문단·읽기 순서·표·그림·Markdown을 앱에서 다시 만드는 알고리즘으로 대체하지 않습니다.
4. 직접 구현하는 부분은 작업 큐·취소·오류 격리·자동 저장·자산 경로·원본 대조·앱 상태 연결과 검증된 도구의 구체적인 빈틈입니다.
5. SDK가 해결하지 못하는 문제는 한계로 남겨 표시합니다. 임의 교정으로 원문 의미를 바꾸지 않습니다.

## 이번 PDF 적용

- 정상 논문: 기존 GROBID/JATS 경로를 보존합니다.
- 일반 PDF: 공식 [PyMuPDF Document.to_markdown](https://pymupdf.readthedocs.io/en/latest/document.html#Document.to_markdown)을 격리 worker에서 사용합니다. 메인 앱의 PyMuPDF 1.28과 별도 2.0 런타임입니다.
- SDK Markdown은 정본 문자열로 보존합니다. 그림 주소만 공식 위치 정보에 따라 상대 경로로 바꿉니다. 원본 대조는 SDK가 제공하는 쪽·좌표·문자 범위를 사용합니다.
- 화면 표시는 markdown-it-py를 재사용합니다. 문서의 실행 가능한 HTML은 표시하지 않습니다.
- 기존 native/OCR 결과는 SDK 실패 시 보존합니다. 원본 해시 변경·자산 충돌·취소는 성공으로 낮추지 않습니다.
- Docling은 비교·어려운 표 보완에 사용합니다. SDK Markdown을 Docling 결과와 임의 혼합하지 않습니다.
- 자체 `reading_flow` 구현은 제품 경로에서 제거했습니다. 비교 소스·결과는 DevCache에 보존했습니다.

## 실제 확인한 한계

396쪽 책의 49~56쪽 표본에서 SDK가 문단·그림·표와 쪽 번호 제거를 개선했습니다. 그러나 `통 해` 등의 한글 줄 경계 공백, `멜라닌색`/`소가`의 쪽 경계는 남았습니다. 표본 성공은 전체 책 완전성이나 다른 PDF의 정확성 보장이 아닙니다.

공개 [Kiwi.glue](https://bab2min.github.io/kiwipiepy/v0.23.2/kr/#Kiwi.glue)도 별도 시험했습니다. 단어 연결을 개선할 수 있지만 정상 문장 사이를 잘못 붙이는 반례가 있어 기본 경로에는 적용하지 않습니다. KSS 문장 분리는 문단·페이지·그림 배치 복원의 대체물이 아닙니다.

SDK·앱 단위 시험, 전체 책 실행, 실제 frozen worker·설치 프로그램의 검증 상태는 HANDOFF와 검증 기록에 구분해 남깁니다.
