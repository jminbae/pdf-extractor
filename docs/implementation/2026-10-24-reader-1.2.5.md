## 확인된 원인과 역할

- UI 확대는 result-scroll의 article/pre에만 연결돼 원본pane에서는 작동하지 않았습니다. UI worker가 모든 pane의50–250%/배율복귀와 확대된 원본 좌표·검색 회귀를 담당합니다.
- 작은 X가 유일한 목록 복귀였고 전역 추출은 목록 체크값에만 의존했습니다. 기존 closeReader/extract_selected를 재사용해 명시적 목록 복귀·현재 문서 추출과 진행을 제공합니다.
- “원본 미리보기 · 변환” 옆6/71은 실제 변환 진행이 아니라 현재 PDF쪽 탐색이었습니다. 설명은 줄이고 원본 종류에 맞는 접근성 이름과6 / 71 표시를 사용합니다.
- 백엔드는 ThreadingHTTPServer여서 서버 전체 직렬차단은 아닙니다. 그러나 paper()는 source_view()를 먼저 실행하고 UI는 source/map 모두 기다려, 저장된MD마저 LibreOffice 전체변환에 종속됐습니다. root가 결과만 읽는 `/open?mode=result`를 추가하고 UI에서 원본·좌표맵을 필요할 때 준비합니다.
- preview.py는 원문SHA1/renderer별 잠금과 완료캐시를 이미 사용합니다. debugger는 합성71슬라이드/약17MB의 cold/cache/첫PNG와 공식PDF export PageRange/hidden slide를 분리 측정합니다. 원문PPTX가 예전 폴더에 없어 현재 경로를 사용자에게 비동기로 물었으며, 합성 결과를 실제 사용자파일 수치로 표현하지 않습니다.

root: app.py/앱회귀/버전·배포·기록. UI worker: ui.py/실제UI·frozen harness. debugger: preview.py/preview 회귀·성능실측. code-reviewer: 각 변경 직후 독립검수. 사용자 원문·기존 MD/이미지·설정은 검사 시 읽기 전용, 산출물은 DevCache/TEMP에 둡니다.

## 첫 화면 1–2초 요구에 대한 변경

사용자는 캐시 없는 첫 화면도 빠르게 열려야 한다고 명시했습니다. LO 전체 변환을 다소 줄이는 것으로는 이 요구를 충족하지 못하므로 공개 `@aiden0z/pptx-renderer` 1.4.0의 수정 없는 standalone 번들을 선택했습니다. 조사 근거·원문 고지·성능 측정 조건은 [fast PPTX 연구](../research/2026-10-24-fast-pptx.md)에 있습니다. 앱은 슬라이드 레이아웃을 직접 구현하지 않고 공식 lazySlides/lazyMedia, renderSlideToContainer, 검색·강조 API를 사용합니다.

- 새 backend는 PPTX에서 presentation.xml과 관계 파일로 순서·크기만 확인하고 원본 revision에 묶인 입력을 제공합니다. 원본·MD를 보기 위해 전체 PDF 변환을 선행하지 않습니다.
- 렌더러는 `sandbox=allow-scripts`인 opaque iframe 안에서 실행합니다. 부모는 선택한 원본 바이트만 전송하며 nonce·문서 세대·revision으로 메시지를 제한합니다. 외부 media·접속은 차단하고 native API를 전달하지 않습니다. 실제 frozen WebView2에서도 bridge 부재를 확인하기 전에는 격리 완료로 보지 않습니다.
- 한 번에 한 슬라이드 handle만 mount하고, 이동·확대 시 이전 handle을 dispose합니다. 이미지가 늦게 생기는 경우를 놓치지 않도록 handle.ready→실제 그림 decode→fonts→2RAF를 준비 완료 기준으로 삼습니다. PDF 보기 fallback은 사용자가 선택하는 별도 경로입니다.
- 기존 EMU 좌표를 정확한 화면 좌표로 추정하지 않습니다. native 항목은 논리적인 슬라이드 힌트만 유지하며, 공식 렌더러에서 같은 슬라이드의 전체 문장이 하나로 확인되는 경우에만 문단 대응을 사용합니다.
- 공개 번들 SHA256 `eed96db79a8300ef66a57e8a5f4f2c06a5cb78ac30b7eecd5df921c05ac5069b`와 18개 의존성·24개 고지를 고정했습니다. MPL 해당 소스도 설치 폴더의 `licenses/pptx_renderer/sources`에 실물로 동봉합니다. 빌드 helper는 정확한 archive를 검증해 DevCache에 구성하고 이미 다른 출력이 있으면 보존·실패합니다. 오프라인 8시험, 실제 캐시 및 HTTPS fallback, 독립 검수를 통과했습니다.
