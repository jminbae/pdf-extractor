# 1.2.5 공통 문서 보기와 미리보기 지연 개선

## 작업 중

기준은 공개·설치된1.2.4와 최종 기록 commit `a1f19f8feca8e93e2c8a89677d4a4418c4357aa1`입니다. 사용자는 PPTX 로딩, 원본 Ctrl+휠 무효, 목록 복귀 발견성, 보기에서 해당 문서 추출, 모호하고 오래된 화면을 제보했습니다. 기존 문서 목록 중심 구성은 유지하고 짧은 표시·일관된 조작으로 개선합니다. 새 버전 공개·설치 전에는 완료로 보고하지 않습니다.

## 확인된 원인과 역할

- UI 확대는 result-scroll의 article/pre에만 연결돼 원본pane에서는 작동하지 않았습니다. UI worker가 모든 pane의50–250%/배율복귀와 확대된 원본 좌표·검색 회귀를 담당합니다.
- 작은 X가 유일한 목록 복귀였고 전역 추출은 목록 체크값에만 의존했습니다. 기존 closeReader/extract_selected를 재사용해 명시적 목록 복귀·현재 문서 추출과 진행을 제공합니다.
- “원본 미리보기 · 변환” 옆6/71은 실제 변환 진행이 아니라 현재 PDF쪽 탐색이었습니다. 설명은 줄이고 원본 종류에 맞는 접근성 이름과6 / 71 표시를 사용합니다.
- 백엔드는 ThreadingHTTPServer여서 서버 전체 직렬차단은 아닙니다. 그러나 paper()는 source_view()를 먼저 실행하고 UI는 source/map 모두 기다려, 저장된MD마저 LibreOffice 전체변환에 종속됐습니다. root가 결과만 읽는 `/open?mode=result`를 추가하고 UI에서 원본·좌표맵을 필요할 때 준비합니다.
- preview.py는 원문SHA1/renderer별 잠금과 완료캐시를 이미 사용합니다. debugger는 합성71슬라이드/약17MB의 cold/cache/첫PNG와 공식PDF export PageRange/hidden slide를 분리 측정합니다. 원문PPTX가 예전 폴더에 없어 현재 경로를 사용자에게 비동기로 물었으며, 합성 결과를 실제 사용자파일 수치로 표현하지 않습니다.

root: app.py/앱회귀/버전·배포·기록. UI worker: ui.py/실제UI·frozen harness. debugger: preview.py/preview 회귀·성능실측. code-reviewer: 각 변경 직후 독립검수. 사용자 원문·기존 MD/이미지·설정은 검사 시 읽기 전용, 산출물은 DevCache/TEMP에 둡니다.

## 현재 검증

- root 신규2회귀에서 기존 코드는 result 읽기 중 preview 호출1회 및 단위 라벨 부재로 기대 실패했습니다. 구현 후 workflow/snapshot22개 PASS(3.157초), 신규2개 독립검수 PASS(0.330초). XLSX 한시트가 여러 인쇄쪽이 될 수 있으므로 탐색 단위는쪽입니다.
- UI 원본 Ctrl+휠 첫 RED는 실제 trusted 입력 후폭1000→1000/배율없음으로 확인했습니다. 공통pane 확대 GREEN과 새 보기 흐름은 검증 중입니다.
- 실제 사용자 앱의 예전PID31116은 종료됐고 현재 동일 실행파일명 프로세스는 관측되지 않았습니다. 원문 폴더에는 책PDF와MD1개만 남아 있으며 사용자 이동·삭제를 되돌리지 않습니다.
- `preview-1.2.5-benchmark/receipt.json`의 합성71장/17,563,348bytes: 기존전체 cold10.051초 중LO9.935초, cache35–41ms, renderer.open6.1ms/첫PNG65ms. 공식PageRange1도8.234초여서 전체와 중복 실행하는 방식은 추가하지 않았습니다. 별도strict quality 영수증에슬라이드순서·픽셀동등·원문/TEMP정리를 기록했습니다.
- 공식 `ExportHiddenSlides=true`로 추출과 미리보기의 숨김 슬라이드 순서를 맞추고 프레젠테이션 캐시는v4로 분리했습니다. 취소가능한잠금대기 신규3RED→8GREEN(0.078초), 독립8PASS(0.075초). `preview-1.2.5-public-smoke.json`은 실제공개API+LibreOffice+합성3슬라이드에서01/02/03순서/cold7.495초/cache17.6ms/원문불변/TEMP제거PASS입니다. PowerPointCOM은 메인환경pywin32없음과공유instance위험으로 생성·설치·생산추가하지 않았습니다.
- `deployment-backup-1.2.5/receipt.json`: 현재1.2.4프로그램·사용자자료와실제settings194파일SHA/bytes백업, 원본책SHA불변. 앞선백업은보존하며 사용자앱정상실행전보존확인은설치후별도수행합니다.
