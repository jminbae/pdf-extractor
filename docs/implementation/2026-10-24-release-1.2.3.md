## 변경과 검증 범위

- 문서마다 독립 프로세스를 소유하며, 무거운 PDF/SDK/OCR 처리가 화면 프로세스의 GIL을 막지 않도록 분리했습니다. 모니터 스레드는 이벤트 전달과 종료 감시만 담당합니다.
- CPU 코어와 메모리 여유에 따라 새 작업을 시작합니다. 동시 실행 상한은 10개이며 이 기기의 물리16/논리24코어에서는 8개입니다. 문서 수를 넘겨 요청하면 대기열에 남고, 여유가 생기면 자동 시작합니다.
- 메모리 정책은 새 작업의 진입 제어입니다. 실행 중인 작업에 강제 메모리 한도를 부과하거나 자동 종료한다고 주장하지 않습니다. 초기 PDF 예약은 2GiB, Office는 512MiB, 텍스트는 128MiB이며 관측한 피크의 120%로 보수적으로 갱신합니다.
- 새 작업을 포함한 앱 메모리 예산은 물리 RAM의 50%, 시스템 여유는 15%와 2GiB 중 큰 값입니다. 시스템 CPU 90% 이상이면 새 작업을 기다립니다. 소형 PC의 1개 작업 예외도 최소 512MiB 여유를 요구합니다.
- Windows 문서 자식과 SDK 후손은 `BELOW_NORMAL_PRIORITY_CLASS`, 화면은 `NORMAL_PRIORITY_CLASS`를 유지하는 것을 실제 실행 파일에서 확인했습니다.
- 모든 신규·재추출 PDF는 공통 SDK 경로로 시작합니다. 텍스트 보존 검사를 통과하지 못한 경우에만 native/OCR로 보완합니다. 논문 메타데이터 조회나 GROBID를 먼저 실행하지 않습니다.
- 같은 내용의 문서는 겹쳐 추출하지 않으며, 서로 다른 원본이 같은 파일명을 가질 때 저장 충돌을 OS 파일 잠금으로 막습니다. 취소·실패가 다른 문서의 완료 결과를 무효화하지 않습니다.

전체 책 실행의 원래 `receipt.json`은 실행 중 스케줄러 소스가 바뀌어 `ok=false`입니다. 이를 덮어쓰지 않았습니다. 별도 변환 검증은 SDK 핵심 소스·결과·원본 불변과 내용 보존을 확인하며, 이후 빌드의 전체 책 완주를 대신했다고 주장하지 않습니다.

최종 실행 파일의 숨김 창 시험 `frozen-1.2.3-priority-book/receipt.json`도 브라우저 HTTP callback 1회가 2초를 초과하여 `ok=false`로 보존했습니다. 같은 실행에서 bridge와 Node HTTP는 빠르게 응답했고, 책 실행 중 CSV가 별도 PID에서 완료되었으며 검색·중지·기존 MD 유지가 확인됐습니다. 이 실패를 API 서버나 PDF 작업의 GIL 정지와 동일시하지 않습니다. CDP 왕복은 별도 진단값이며, 모든 실제 입력부터 화면 그리기까지 2초를 보장한 시험은 아닙니다.

`frozen-1.2.3-priority-book-foreground`의 브라우저 플래그 실험은 이 기기의 승격 환경에서 실제 적용을 확인하지 못해 유효하지 않은 실패로 보존했습니다. 제품 실행 설정에는 이 플래그를 넣지 않았습니다.

최종 대조는 같은 `7a634a…` 실행 파일에 시험 전용 공식 CDP `Emulation.setFocusEmulationEnabled`를 적용했습니다. 적용 전 `hasFocus=false/visibility=hidden`, 적용 후와 4회 관측·검색·취소 시점에 `hasFocus=true/visibility=visible/hidden=false`, 마지막 해제 성공을 확인했습니다. 제품 설정은 바꾸지 않았습니다.

이 조건의 4회 bridge는 3.6/3.6/11.0/2.6ms, Node HTTP는 4/2/2/1ms, 브라우저 HTTP는 5.0/86.2/3.8/2.8ms로 기존 2초 기준을 통과했습니다. 실제 처리 쪽은 0/0/0/28이며, 추가 CSV는 책과 다른 PID에서 저장됐습니다. 검색은 108.6ms·12건, 중지는 463ms에 31쪽에서 `paused`, 기존 MD·검색어 유지·미완료 MD 비공개·원본 SHA 불변·소유 TEMP 정리를 확인했습니다. 비교 화면의 합성 PNG 캡처 1개가 저장됐으며 목록 캡처는 timeout으로 미저장입니다. 이를 실제 보이는 창의 모든 입력→그리기 성능 보장이나 숨김 지연의 정확한 원인 확정으로 확대하지 않습니다. 앞선 기본 hidden 실패와 무효 플래그 실험은 그대로 남깁니다.
